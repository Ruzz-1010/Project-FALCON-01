    01 / THE OCEAN

    01 / OBJECTIVES

    Phase 1 Objectives

    Phase 1 is integration and evaluation, not sensor invention. Six objectives frame the work.

    PHASE 1 OBJECTIVES
    1. Design a serviceable solar-powered buoy with passive mooring.
    2. Acquire pressure and wind measurements with supporting telemetry.
    3. Estimate wave height from underwater pressure with explicit calibration.
    4. Transmit via LoRa to a shore Bay Station for storage, processing and dashboard.
    5. Evaluate accuracy, reliability, latency, power use and usability.
    6. Develop and evaluate short-term AI wave prediction against a baseline.

    02 / HARDWARE BASELINE

    Offshore Sensing Node

    Buoy: ESP32 controller, underwater pressure sensor, wind speed and direction sensors, GPS for position, time and geofence, battery and solar power, LoRa transceiver. Shore: Bay Station mini PC with LoRa receiver, local storage and processing.

    08 / AI PREDICTION REQUIREMENT

    Short-Term Wave Height Prediction

    Target: short-term wave-height prediction 5, 10 and 15 minutes ahead. Currently a transparent trend baseline. Evaluation requires calibrated data, a chronological train / validation / test split, and MAE, RMSE and bias reporting. This is not a trained model result yet.

    09 / DASHBOARD, SECURITY AND HEALTH

    Four-Page Dashboard and Security States

    Four-page dashboard: Overview, Buoy Motion, Sensors, Logs & Alerts. Grouped telemetry endpoint with explicit states LIVE / SIMULATED / ESTIMATED.

    SECURITY AND HEALTH

    Security states: SECURE, WARNING, ALERT, DISARMED. GPS geofence persistence, vibration / tamper detection and the enclosure switch support buoy health. Normal wave motion must not generate alerts; false-positive testing is required.

    10 / VALIDATION & STATUS

    How Each Claim Will Be Tested

    Nothing in this prototype is claimed as validated yet. Each measurement path has a defined test before it earns a number.

    BENCH SENSOR TESTS→PRESSURE-TO-WAVE vs REFERENCE→WIND vs REFERENCE ANEMOMETER→GPS GEOFENCE→VIBRATION / TAMPER→POWER BUDGET

    Plus LoRa packet loss, latency, range and buffering; dashboard usability on desktop, tablet and phone; and AI evaluation against the persistence baseline.

    Implemented
    Firmware shell · captive portal · telemetry framing · Bay Station service prototype (simulator, SQLite, REST API, dashboard) · grouped telemetry endpoint · pressure-based wave estimate simulation · GPS geofence simulation
    Not yet validated
    Final sensor models and calibration coefficients · real GPS and tamper performance · LoRa hardware selection and range · field-trained AI

    Implemented means the software path exists and runs. It does not mean the measurement is accurate.

    11 / SCOPE & RISKS

    What It Does Not Do — and How Risks Are Handled

    13 / IMPACT & FUNDING

    Who it serves — and what it costs

    The first pilot should solve one verified problem for one identified coastal user before the project expands. No site or beneficiary is confirmed yet. The request pays for a complete 5-month development and testing process — midpoint ~₱115,000 of the ₱90,000–₱150,000 planning range.

    Beneficiaries are intended, not committed partners. Planning range only, not a supplier quotation — budget replaced with current quotations (3-supplier canvass) before submission.

    WHERE THE INNOVATION ACTUALLY ISThe contribution is the affordable, documented integration and local evaluation of established sensing, LoRa telemetry, shore processing, solar power, security telemetry and transparent prediction research. It is not the invention of a new sensor, buoy or AI algorithm.
